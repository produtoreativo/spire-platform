# Incident Analysis

## Required Sections

- Incident identifier and date.
- Impact summary.
- Customer or product effect.
- Timeline.
- Detection source.
- Response actions.
- Contributing factors.
- What worked.
- What did not work.
- Follow-up actions.
- Evidence links.
- Decision Trail entry.

## Analysis Rules

- Separate facts from hypotheses.
- Avoid blame language.
- Connect actions to observable signals.
- Identify missing telemetry.
- Convert lessons into backlog items, runbook updates, or reliability plan changes.
